# wayland-vnc v1.0.3

A release-plumbing release. The `wayland-vnc` package behaves exactly as in v1.0.2 and
the GNOME backend `wayland-vnc-grd` as in v1.0.1. What changes is how a release reaches
people: the PPA upload now works for both source packages, so this is the first
release since v1.0.0 to be published everywhere.

## Why v1.0.1 and v1.0.2 were never published

The release workflow uploads two source packages to `ppa:ventura8/wayland-vnc`:
`wayland-vnc`, then `wayland-vnc-grd`. From v1.0.1 on, Launchpad's anonymous FTP
accepted the first upload of a run and answered the second with
`550 Requested action not taken: internal server error` -- on v1.0.1, and on both runs of
v1.0.2. The GitHub release job waits on the upload, so neither tag produced a GitHub
release, and the PPA kept `wayland-vnc-grd` at 1.0.0 while `wayland-vnc` moved on.
mixxx hit the same failure the same week and moved to SFTP
([mixxxdj/mixxx#17107](https://github.com/mixxxdj/mixxx/pull/17107)).

This release carries everything in those two: see
[v1.0.1](v1.0.1.md) (SonarQube Cloud in CI, the GNOME resize fix, the KVM qualification
campaign) and [v1.0.2](v1.0.2.md) (every SonarQube finding fixed in code, the pinned
AppImage runtime, the lock-screen harness fix). For a PPA user on GNOME, this is the
upload that brings the resize fix -- a session that follows a change of the mirrored
monitor's size instead of freezing on its last frame.

## Install

### Ubuntu 26.04 (PPA)

The release tag uploads two source packages to `ppa:ventura8/wayland-vnc`
(Launchpad builds them shortly after): `wayland-vnc`, and for GNOME desktops the patched
GNOME Remote Desktop backend `wayland-vnc-grd`, built from the pinned upstream sources.
Their changelogs say what the release gate found: for this release, *not
release-qualified*.

```sh
sudo add-apt-repository ppa:ventura8/wayland-vnc
sudo apt update && sudo apt install wayland-vnc
sudo apt install wayland-vnc-grd   # GNOME desktops
```

### GitHub release assets

Every release publishes `.deb`, `.rpm` (Fedora/EL/openSUSE), Arch `.pkg.tar.zst`,
AppImage, Flatpak, and Snap binaries plus a `SHA256SUMS` manifest. Verify before
installing a downloaded asset:

```bash
sha256sum --ignore-missing -c SHA256SUMS   # checks only the assets you downloaded
sudo apt install ./wayland-vnc_1.0.3_all.deb           # Debian/Ubuntu
sudo dnf install ./wayland-vnc-1.0.3-1.*.noarch.rpm    # Fedora/EL
```

On a GNOME desktop that does not use the PPA, also install the patched GNOME Remote
Desktop backend from the assets; the distribution's own crashes whenever a viewer
disconnects:

```bash
sudo apt install ./wayland-vnc-grd_1.0.3_amd64.deb
```

## What is in this release

### PPA uploads over SFTP

[`scripts/ppa-upload.sh`](../../scripts/ppa-upload.sh) now performs both uploads. It
authenticates to Launchpad over SFTP as the PPA's owner with a dedicated upload key (the
`PPA_SSH_PRIVATE_KEY` secret in the `ppa-release` environment), offers only that key,
and trusts only Launchpad's host key as pinned in
[`packaging/launchpad-known-hosts`](../../packaging/launchpad-known-hosts). Without the
secret the upload fails naming it; it never falls back to FTP.

### A re-run finishes a half-done release

Before uploading, the script asks Launchpad whether the PPA already records that exact
source version. Launchpad refuses a version it has ever accepted, so re-running a
release job whose first upload went through used to upload it again for nothing; now
that package is reported and skipped, and the re-run completes the rest -- including
the GitHub release, which waits on the upload.

The one-time set-up (the key, its Launchpad registration, the secret) is in
[`docs/ppa-setup.md`](../ppa-setup.md).

## Compatibility status

**No desktop is release-qualified at this tag.** `qualification/records.json` is
intentionally empty, and the release gate stays red until all fourteen target/viewer
pairs pass on a trusted runner and their records are published to the evidence store for
the exact commit that is tagged (`docs/evidence-store.md`).

The serving path is unchanged since v1.0.2, whose branch was validated on real hardware
and in the KVM campaign with the actual RealVNC viewers (see
[v1.0.2](v1.0.2.md#compatibility-status)): Sway, Wayfire, Xfce on labwc, LXQt on labwc
and KDE Plasma passed with both viewers; GNOME all but `lock`, which GNOME Shell refuses
by design; Hyprland is blocked by an upstream aquamarine defect on a live switch to 4K.
Those runs were on earlier commits, so they are not evidence for this tag.
