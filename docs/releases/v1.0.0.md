# wayland-vnc v1.0.0

Evidence-gated, Wayland-only VNC compatibility toolkit for the actual RealVNC Viewer,
now shipped as a full multi-format installer with CI, PPA, and GitHub release
automation.

## Install

### Ubuntu 26.04 (PPA)

The release tag uploads two source packages to `ppa:ventura8/wayland-vnc`
(Launchpad builds them shortly after): `wayland-vnc`, and for GNOME desktops the patched
GNOME Remote Desktop backend `wayland-vnc-grd`, built from the pinned upstream sources.
Their changelogs say what the release gate found: for this release, *not
release-qualified*.

```sh
sudo add-apt-repository ppa:ventura8/wayland-vnc
sudo apt update && sudo apt install wayland-vnc
sudo apt install wayland-vnc-grd   # GNOME desktops
```

### GitHub release assets

Every release publishes `.deb`, `.rpm` (Fedora/EL/openSUSE), Arch `.pkg.tar.zst`,
AppImage, Flatpak, and Snap binaries plus a `SHA256SUMS` manifest. Verify before
installing a downloaded asset:

```bash
sha256sum -c SHA256SUMS
sudo apt install ./wayland-vnc_1.0.0_all.deb           # Debian/Ubuntu
sudo dnf install ./wayland-vnc-1.0.0-1.*.noarch.rpm    # Fedora/EL
```

On a GNOME desktop that does not use the PPA, also install the patched GNOME Remote
Desktop backend from the assets; the distribution's own crashes whenever a viewer
disconnects:

```bash
sudo apt install ./wayland-vnc-grd_1.0.0_amd64.deb
```

## First run

Launch the setup menu (install / diagnostics / uninstall):

```bash
wayland-vnc-setup
```

or drive it directly:

```bash
wayland-vnc doctor            # read-only capability diagnostic
wayland-vnc set-password      # store the viewer credential (mode 600)
systemctl --user enable --now wayland-vnc.service
```

The server listens on `127.0.0.1:5900` by default: this machine only. To let a phone
or another computer on the same Wi-Fi or LAN connect, turn on **Local Network Access**
in the settings app; the server then binds every interface and is reachable from every
network this machine is on. There is no fence beyond that switch -- systemd applies
`IPAddressAllow` only from a privileged manager, never from a user one -- so do not
forward port 5900 through a router or expose it beyond the local network without a
tunnel. Authentication is always on, and a random password is generated on first
start.

## What is in this release

- **Full installer product.** A WayVNC systemd **user** service, provisioning
  (`set-password`, `provision`, `--stdin` for automation), the `serve` ExecStart path
  (loopback bind by default, local network as an explicit switch, fail-closed on
  anything but a native Wayland session and on a backend the probe did not select),
  and a read-only
  `doctor`/`status` diagnostic. A launcher TUI (`wayland-vnc-setup`) offers install,
  diagnostics, and — once installed — uninstall.
- **Multi-format packaging** sharing one payload staging script: deb, rpm, Arch,
  AppImage, Flatpak, Snap.
- **Real install/uninstall smoke** across platforms (Ubuntu 26.04, Debian trixie,
  Fedora 44, AlmaLinux 10, openSUSE Tumbleweed, Arch) covering happy and failure
  scenarios: install, reinstall, truncated-package rejection, provisioning
  permissions, serve fail-closed, and clean remove/purge with no leftovers.
- **Isolated Wayland fixtures + actual-viewer qualification** for GNOME, KDE Plasma,
  Xfce+labwc, LXQt+labwc, Sway, and Wayfire, driven unattended through a viewer
  harness (keyboard, pointer, scroll, drag, session lock, monitor hot-plug, resize,
  4K, portal decisions). Hyprland runs in a KVM guest, where suspend-resume passes;
  the Android RealVNC app has been exercised by hand against a real GNOME laptop and
  the defects it exposed are fixed and packaged.
- **Native patch series** for GNOME Remote Desktop, LibVNCServer, and TigerVNC
  `w0vncserver`, built from checksum-pinned upstream sources with ASan/UBSan
  regressions. Five of the GNOME Remote Desktop and LibVNCServer patches were found
  with the actual RealVNC Viewer (Android, and for the last one Windows) on a real
  GNOME laptop and each is reproduced without the phone: the crash on client
  disconnect, the announced colour depth the ZRLE encoder does not honour, hung-up
  clients stranded in the single session queue, an update sent in the old pixel
  format right after a format change, and the daemon SIGKILLed mid-stream at 4K by
  the kernel's realtime watchdog because libpipewire had made its data loop a
  realtime thread with a 200 ms budget. They ship as the `wayland-vnc-grd` package.
- **A GTK4/libadwaita settings app** translated into 101 languages (every language
  Ubuntu-Hello supports), following the desktop's language by default, with
  diacritics-tolerant search in the language chooser and in Diagnostics, a
  verified right-to-left layout, and an About dialog. A translation lint fails the
  build on any missing message.
- **GNOME robustness at login**: the service requires the VNC listener to belong to
  this session's daemon (a second short-lived session of the same user can hold the
  port for a moment) and adopts the daemon's keyring password into the stored
  credential when the two drift.
- **Suspend-resume is now a runnable scenario**: `qualify-desktop.py --kvm` drives
  a KVM guest through the QEMU guest agent and takes it through real ACPI S3 with
  the viewer connected; it passes on the Hyprland guest.
- **CI + release automation**: `.github/workflows/ci.yml` (lint, unit+coverage,
  native sanitizers, fixture-smoke matrix, package-smoke matrix) and
  `.github/workflows/release.yml` (tag → PPA source upload, all-format build, GitHub
  release with checksums).
- **Agent files and skills** under `.agents/skills/` plus an expanded `AGENTS.md`.

## Compatibility status

No desktop is release-qualified yet: `qualification/records.json` is intentionally
empty and the release gate stays red until all fourteen target/viewer pairs pass on a
trusted runner. Fixture evidence gathered so far is partial and private.
