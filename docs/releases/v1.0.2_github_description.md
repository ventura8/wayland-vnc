# wayland-vnc v1.0.2 - A pinned AppImage runtime, and every SonarQube finding fixed

A hardening release. The `wayland-vnc` package behaves exactly as in v1.0.1: the payload,
the hardened systemd **user** unit, the default `127.0.0.1:5900` bind and the Local
Network Access switch. The GNOME backend `wayland-vnc-grd` is unchanged.

## Highlights

- **The AppImage embeds a pinned runtime.** appimagetool used to download the runtime it
  writes into every AppImage from type2-runtime's mutable `continuous` release, with no
  checksum. Both the tool and the runtime are now pinned to tagged releases, with a
  SHA-256 per architecture, in one file every AppImage build reads.
- **All 46 open SonarQube findings fixed in code**, none suppressed: base images pinned
  by digest alone, upstream archives verified with `ADD --checksum`, unprivileged lab
  images, HTTPS-only downloads with time limits, and developer scripts that refuse path
  arguments outside the checkout or the temp directory.
- **The settings app** reads and writes its language preference as explicit UTF-8.
- **The desktop viewer can wake a lock screen.** The harness refused the single space
  that wakes GNOME's and Plasma's lock screens, which failed Plasma's `lock` and left it
  locked for `monitor-change`. Plasma now passes every runnable scenario with both
  viewers.
- **CI lints every shell file**, not only the top level of `scripts/` and `packaging/`.

## Install

```sh
sudo add-apt-repository ppa:ventura8/wayland-vnc
sudo apt update && sudo apt install wayland-vnc
sudo apt install wayland-vnc-grd   # GNOME desktops
```

Or from the assets below -- `.deb`, `.rpm`, Arch `.pkg.tar.zst`, AppImage, Flatpak and
Snap, with a `SHA256SUMS` manifest. Verify first:

```bash
sha256sum --ignore-missing -c SHA256SUMS   # checks only the assets you downloaded
sudo apt install ./wayland-vnc_1.0.2_all.deb
```

## Status

**No desktop is release-qualified at this tag.** The gate stays red until all fourteen
target/viewer pairs pass on a trusted runner and their records are published to the
evidence store for the exact tagged commit.

Before merge, the packaged 1.0.2 passed every hardware-validation phase on a real GNOME
laptop with RealVNC Viewer 7.15.1, and the KVM campaign ran every target with the actual
RealVNC viewers, desktop and Android. Sway, Wayfire, Xfce on labwc and LXQt on labwc
passed every scenario with both; KDE Plasma every runnable one. GNOME passed all but
`lock`, which GNOME Shell refuses by design. Hyprland is blocked by an upstream
aquamarine defect on a live switch to 4K. Those runs were on the commits before the tag,
so they are not evidence for it.
