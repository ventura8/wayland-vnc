# wayland-vnc v1.0.2

A hardening release. The `wayland-vnc` package behaves exactly as in v1.0.1: the
payload, the hardened systemd **user** unit, the default `127.0.0.1:5900` bind and the
Local Network Access switch. The GNOME backend `wayland-vnc-grd` is unchanged. What
changed is how the project's own artifacts are built and checked: every open SonarQube
finding was fixed in code, the AppImage stopped embedding an unverified runtime, and a
hardware validation of the whole branch found two harness defects, both fixed here.

## Install

### Ubuntu 26.04 (PPA)

The release tag uploads two source packages to `ppa:ventura8/wayland-vnc`
(Launchpad builds them shortly after): `wayland-vnc`, and for GNOME desktops the patched
GNOME Remote Desktop backend `wayland-vnc-grd`, built from the pinned upstream sources.
Their changelogs say what the release gate found: for this release, *not
release-qualified*.

```sh
sudo add-apt-repository ppa:ventura8/wayland-vnc
sudo apt update && sudo apt install wayland-vnc
sudo apt install wayland-vnc-grd   # GNOME desktops
```

### GitHub release assets

Every release publishes `.deb`, `.rpm` (Fedora/EL/openSUSE), Arch `.pkg.tar.zst`,
AppImage, Flatpak, and Snap binaries plus a `SHA256SUMS` manifest. Verify before
installing a downloaded asset:

```bash
sha256sum --ignore-missing -c SHA256SUMS   # checks only the assets you downloaded
sudo apt install ./wayland-vnc_1.0.2_all.deb           # Debian/Ubuntu
sudo dnf install ./wayland-vnc-1.0.2-1.*.noarch.rpm    # Fedora/EL
```

On a GNOME desktop that does not use the PPA, also install the patched GNOME Remote
Desktop backend from the assets; the distribution's own crashes whenever a viewer
disconnects:

```bash
sudo apt install ./wayland-vnc-grd_1.0.2_amd64.deb
```

## What is in this release

### The AppImage runtime is pinned

appimagetool writes a small ELF runtime -- the stub that mounts the squashfs -- at the
front of every AppImage. Unless it is handed one, it downloads that runtime from
type2-runtime's mutable `continuous` release with no checksum. v1.0.1 pinned the tool
but not the runtime, so every AppImage still shipped whatever `continuous` held on the
day it was built.

[`packaging/appimage-pins.sh`](../../packaging/appimage-pins.sh) now pins both for
every AppImage build, the release build and the portable smoke alike: appimagetool
1.9.1 and runtime `20251108`, a SHA-256 per architecture for each, fetched over HTTPS
only (redirects included) with bounded time, re-verified from cache on every run, and
passed to the tool with `--runtime-file`. The runtime digests were checked against the
release's own GPG signatures when they were pinned. On x86_64 and aarch64 the build now
downloads no runtime, and the AppImage's runtime matches the pinned file byte for byte
except the 16-byte digest field appimagetool fills in.

### SonarQube: every open finding fixed in code

All 46 findings open on `ventura8_wayland-vnc` were fixed in the code. None was
suppressed, marked "won't fix", or switched off in the quality profile.

- **Container images.** Each base is pinned by digest alone: a tag beside a digest is
  never read, and only suggested a version the digest might not hold. The GNOME and
  Plasma fixture build stages verify their upstream archives with `ADD --checksum`
  against the same `sources.json` digests, instead of `curl | sha256sum -c`, and no
  longer install curl. hadolint moves to v2.14.0, which parses that flag. The checks
  image copies named paths rather than the whole build context, and it and the Android
  lab image run as an unprivileged account.
- **Downloads.** The KVM cloud image and appimagetool are fetched over HTTPS for the
  request and every redirect, with connect and transfer time limits, so a stalled
  mirror cannot hang a release job or a guest build.
- **Developer scripts** that take a path argument resolve it and refuse it unless it
  lies under the working directory, the checkout or the temp directory.
  `publish-evidence.py` runs git inside the evidence store instead of passing the
  store's path to git as an argument.
- **Product.** The settings app reads and writes its language preference as explicit
  UTF-8, no longer depending on the locale's encoding. The fixture checker takes its
  runtime directory from `XDG_RUNTIME_DIR` rather than a hard-coded `/tmp` path. The
  Android driver's uiautomator attribute pattern scans a long unquoted run once.

### Qualification harness

- **The desktop viewer could not wake a lock screen.** GNOME's and Plasma's lock
  screens show their password prompt only after a key press, and the scenario sends a
  single space. The desktop harness typed only alphanumeric words, so on a KVM guest
  Plasma's `lock` scenario died on a `ValueError` and left the desktop locked, and
  `monitor-change`, which ran next, found no desktop to capture. The space is now sent
  as a key event. With the fix, Plasma passes every runnable scenario with the desktop
  viewer too.
- **The hardware validation installed the previous release.** Its default package path
  still named 1.0.0 after the 1.0.1 bump. It now follows `VERSION`.

### Tooling

- CI lints every shell file, found the way the local gate finds them. It used to glob
  only the top level of `scripts/` and `packaging/`, so `scripts/kvm/` and
  `packaging/snap/` were linted on a laptop and never in CI.
- ruff 0.16.9 and pylint 4.0.9 (Dependabot); the tree stays clean on both.

## Compatibility status

**No desktop is release-qualified at this tag.** `qualification/records.json` is
intentionally empty, and the release gate stays red until all fourteen target/viewer
pairs pass on a trusted runner and their records are published to the evidence store for
the exact commit that is tagged (`docs/evidence-store.md`).

The whole branch was validated before merge. On the maintainer's GNOME laptop (4K,
RealVNC Viewer 7.15.1) the packaged 1.0.2 passed every hardware-validation phase:
install, app drawer, service, password, loopback and LAN viewer sessions, a wrong
password refused, Local Network Access on and off, uninstall and reinstall. On a
Raspberry Pi 5 (arm64) the unit suite, the deb smoke and the Sway, labwc and GNOME
fixture smokes passed natively. The KVM campaign ran every target with the actual
RealVNC viewers, desktop and Android (4.9.4, signature-pinned), on the commits leading
to this release -- which moved afterwards, so none of it is evidence for the tag:

| Target | Desktop viewer | Android viewer | Open |
| --- | --- | --- | --- |
| Sway | passed | passed | -- |
| Wayfire | passed | passed | -- |
| Xfce on labwc | passed | passed | -- |
| LXQt on labwc | passed | passed | -- |
| KDE Plasma | every runnable scenario | every runnable scenario | `portal-revoke` not-run |
| GNOME | all but `lock` | all but `lock` | `lock` fails by GNOME's design |
| Hyprland | fails `4k-200`, `suspend-resume` | fails `4k-200` | upstream aquamarine defect |

GNOME Shell ends remote sessions while the screen is locked, so `lock` cannot pass on
GNOME. Hyprland's live switch to 4K is committed with the old framebuffer still attached
([`aquamarine-01`](../upstream/aquamarine-01-modeset-with-stale-framebuffer.md)). A
blocked target is not a passed one, and this release claims none of them.
