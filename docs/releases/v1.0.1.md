# wayland-vnc v1.0.1

A quality release. The `wayland-vnc` package behaves exactly as in v1.0.0: the payload,
the hardened systemd **user** unit, the default `127.0.0.1:5900` bind and the Local
Network Access switch. The GNOME backend `wayland-vnc-grd` gains one fix: a VNC session
now follows a resize of the mirrored monitor instead of freezing on its last frame. The
rest is how the project is checked -- static analysis beside the pinned linters, locally
and in CI, a qualification campaign against the actual RealVNC viewers -- and the
defects those found.

## Install

### Ubuntu 26.04 (PPA)

The release tag uploads two source packages to `ppa:ventura8/wayland-vnc`
(Launchpad builds them shortly after): `wayland-vnc`, and for GNOME desktops the patched
GNOME Remote Desktop backend `wayland-vnc-grd`, built from the pinned upstream sources.
Their changelogs say what the release gate found: for this release, *not
release-qualified*.

```sh
sudo add-apt-repository ppa:ventura8/wayland-vnc
sudo apt update && sudo apt install wayland-vnc
sudo apt install wayland-vnc-grd   # GNOME desktops
```

### GitHub release assets

Every release publishes `.deb`, `.rpm` (Fedora/EL/openSUSE), Arch `.pkg.tar.zst`,
AppImage, Flatpak, and Snap binaries plus a `SHA256SUMS` manifest. Verify before
installing a downloaded asset:

```bash
sha256sum -c SHA256SUMS
sudo apt install ./wayland-vnc_1.0.1_all.deb           # Debian/Ubuntu
sudo dnf install ./wayland-vnc-1.0.1-1.*.noarch.rpm    # Fedora/EL
```

On a GNOME desktop that does not use the PPA, also install the patched GNOME Remote
Desktop backend from the assets; the distribution's own crashes whenever a viewer
disconnects:

```bash
sudo apt install ./wayland-vnc-grd_1.0.1_amd64.deb
```

## What is in this release

### Static analysis, locally and in CI

SonarQube Cloud analyses the project `ventura8_wayland-vnc` on top of the pinned
linters, looking at what a line-oriented linter cannot see: duplication across files,
cognitive complexity, unreachable state, and security hotspots.

- [`sonar-project.properties`](../../sonar-project.properties) is read by both the local
  run and the CI job, so a finding on a laptop is the finding CI reports. Only per-run
  values -- the token, the project version, the branch -- are passed on the command line.
- [`scripts/run-sonar-scan.sh`](../../scripts/run-sonar-scan.sh) produces coverage from
  the same pinned pytest run the >=90 % per-file gate reads, so the dashboard and the
  gate cannot disagree, and analyses from a digest-pinned scanner container. The token
  is read from the environment, never written to the repository and never placed on a
  command line.
- The `sonar` job in [`ci.yml`](../../.github/workflows/ci.yml) waits on the quality
  gate, so a regression fails the build instead of only colouring a dashboard. It is
  skipped for pull requests from forks: GitHub withholds secrets there, and public PR CI
  must never receive credentials.

Coverage excludes the host-side scripts, the fixtures and the native sources. They are
exercised by the fixture and package smokes, which emit no Python coverage, so counting
them as uncovered source reported a number that meant nothing.

### Defects the analysis found

- **AppImage release build.** The appimagetool checksum was chosen by a `case` with no
  default, so an unexpected architecture reached `sha256sum -c` with an empty checksum
  and the build refused a "tampered" tool it had never heard of. It now fails naming the
  architecture. Seven other switches gained the default they were missing.
- **Android qualification harness.** Two regular expressions backtracked super-linearly
  over their input; both now match in linear time.
- **CLI.** `json.JSONDecodeError` was caught beside the `ValueError` it derives from.
- **Android viewer.** `_enter_credentials` took a UI node it overwrote before reading.
- **Test suite.** Eighteen `pytest.raises` blocks built their own fixtures inside the
  block, so a failure in the set-up would have read as the refusal under test. Four tests
  patched module globals by hand, leaving the module patched for the rest of the session
  if they failed part-way; they use `monkeypatch` now.

### Quality of the rest

Ninety-two composite assertions split one condition per assert, rewritten through the
AST rather than by pattern. Sixty shell conditionals moved to `[[`, which does not
word-split or glob its operands -- except `packaging/snap/serve-daemon.sh`, which is
`#!/bin/sh` and keeps `[`. Duplicated literals became named constants, and the fixture
package lists are sorted, with the package sets verified identical to before.

Eighteen functions were split along seams they already had, with the unit suite
unchanged: among them the image-evidence band scan (which existed twice), the
`/proc` listener lookup, `validate_record`, the TUI menu loop, the diagnostics filter,
the `.po` reader, and the settings-app end-to-end driver, whose 600-line `main` became
one function per scenario group. All 88 of its checks and all 25 of its scenario banners
are still there, and it still passes on all seven platforms it runs on.

### GNOME backend: a resize no longer freezes the session

When the monitor a GNOME session mirrors changes size -- a new resolution or scale in
Settings -- Mutter ends that monitor's screen-cast stream and tells a remote desktop
session nothing; only the PipeWire node goes away. The daemon kept the dead stream, so
the viewer stayed connected to a picture that never changed again. Patch
`0009-follow-mirrored-monitor-resize.patch` watches for the node's removal, records the
primary monitor again, and the viewer receives a DesktopSize update at the new size.
Found with RealVNC Viewer for Android in the GNOME guest; reported upstream as
[`gnome-remote-desktop-04`](../upstream/gnome-remote-desktop-04-mirrored-monitor-resize-freezes.md).

### Pinned dependencies

The Ubuntu 26.04 base-image digest that every fixture Dockerfile and package smoke pins
was refreshed, and so was the Ubuntu cloud image the KVM qualification guests are built
from. That one is pinned against a digest taken from Ubuntu's signed `SHA256SUMS` after
verifying its detached signature against the UEC image signing key, not from the image
alone -- which would only prove the download matched itself. `build-guest.sh` refuses to
build a guest on an image that does not match, so a republished `current/` stops the
campaign instead of quietly changing what the evidence was gathered on.

Every pip pin in `requirements-dev.txt` and every pinned GitHub Action was
already current. gnome-remote-desktop remains pinned at 50.2: upstream 51.0 exists, but
moving to it means rebasing all eight hardened patches, moving the Flatpak runtime from
50 to 51, and re-qualifying GNOME, which is its own release.

## Compatibility status

**No desktop is release-qualified at this tag.** `qualification/records.json` is
intentionally empty, and the release gate stays red until all fourteen target/viewer
pairs pass on a trusted runner and their records are published to the evidence store for
the exact commit that is tagged (`docs/evidence-store.md`).

The campaign ran on this branch against KVM guests, with the actual RealVNC Viewer:
the desktop viewer through the isolated harness, and RealVNC Viewer for Android
(4.9.4, signature-pinned to RealVNC Ltd's release certificate) in the lab AVD. Every
fix it led to moved the tree, so no run below describes the commit that would be
tagged; all fourteen pairs have to be re-run on the final SHA before anything is
published. Where each target stands:

| Target | Desktop viewer | Android viewer | Open |
| --- | --- | --- | --- |
| Sway | passed (`6352b93`) | passed (`26d9ae0`) | -- |
| Wayfire | passed (`6352b93`) | passed (`26d9ae0`) | -- |
| Xfce on labwc | passed (`6352b93`) | passed (`26d9ae0`) | -- |
| LXQt on labwc | passed (`6352b93`) | passed (`26d9ae0`) | -- |
| KDE Plasma | not re-run | every runnable scenario (`008ebb4`) | `portal-revoke` not-run |
| GNOME | not re-run | all but `lock` | `lock` fails by GNOME's design |
| Hyprland | **blocked** | **blocked** | `4k-200`: upstream aquamarine defect |

**Hyprland.** Two failures stacked. At QEMU's default 256 MiB, 3840x2160 swapchains
exhausted virtio-gpu's resource budget (`OUT_OF_MEMORY` to `RESOURCE_CREATE_2D`) and
WayVNC crashed on the fallback; the guests now get `max_hostmem=1G`. What remains is
Hyprland's: a live switch to any larger mode is committed with the old, smaller
framebuffer still attached, which virtio-gpu must refuse, and the output falls back to
800x600. Reduced to plain Hyprland and written up as
[`docs/upstream/aquamarine-01-modeset-with-stale-framebuffer.md`](../upstream/aquamarine-01-modeset-with-stale-framebuffer.md).
A real GPU in the lab should show whether hardware hides it.

**GNOME.** `monitor-change` needed the guest's spare output forced connected
(`video=Virtual-2:e`; firmware EDID alone leaves it disconnected). `suspend-resume` was
Ubuntu's lock-on-suspend: a locked shell refuses new sessions. `resize` was a real
defect in the daemon: when the mirrored monitor changes size, Mutter ends its screen-cast
stream without a word on D-Bus, and the daemon kept the dead stream, so the viewer froze
on the last frame. Patch
`patches/gnome-remote-desktop/0009-follow-mirrored-monitor-resize.patch` records the
monitor again and sends the client a DesktopSize update
([upstream report](../upstream/gnome-remote-desktop-04-mirrored-monitor-resize-freezes.md)).
`lock` cannot pass on GNOME: GNOME Shell inhibits remote access while the screen is
locked (`allowScreencast: false` in the unlock-dialog session mode), which ends every
remote desktop session and refuses new ones until someone unlocks at the machine. A
GNOME desktop therefore cannot be unlocked through wayland-vnc.

That last finding exposed a harness defect: earlier `lock` passes on GNOME were false.
The viewer's "connection closed" message hid the desktop, which read as locked, and
once it was dismissed the Android app showed its last frame again, which read as
unlocked. The scenario now requires the session to be alive both while locked and after
the unlock, and the Android driver treats that message as the end of the session.

**KDE Plasma.** w0vncserver refused every session with `RemoteDesktop: Failed to create
session`, and xdg-desktop-portal-kde logged `zkde_screencast_unstable_v1 does not seem to
be available`. The cause was the guest, not Plasma's session start-up: pam_systemd
(systemd 258+) gives the login session an ambient `CAP_WAKE_ALARM`, which every process
inherits except `kwin_wayland`, whose file capability resets it. The kernel then refuses
KWin the look at a client's `/proc/<pid>/exe` it uses to identify the client, so KWin
withheld its restricted screencast protocol from the portal. The guest session now drops
the ambient set before `dbus-run-session`. Three more guest defects followed it: the
guest's EDID offers 4K at 30 Hz only while the runner asked kscreen-doctor for `@60`,
and the smoke check read KWin's logical geometry (1920x1080 at scale 2) as the mode;
across S3 QEMU reset the root-bus virtio-gpu, so KWin's page flips timed out for good
(the GPU now sits behind a PCIe root port with No_Soft_Reset); and KDE locked the
screen on resume, hiding the desktop from the suspend scenario. With all four fixed,
every runnable Plasma scenario passes with the Android viewer; `portal-revoke` stays
not-run.

One more harness finding: the KVM driver probed `wayvnc --version` for every fixture, so
GNOME and Plasma recorded the shell's `not found` message as their backend version -- a
non-blank string the gate accepts while the evidence says nothing true about what
actually served. It now probes per fixture, as the container driver always did.
