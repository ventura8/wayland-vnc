# wayland-vnc v1.0.1 - Static analysis, and the defects it found

A quality release. The `wayland-vnc` package behaves exactly as in v1.0.0: the payload,
the hardened systemd **user** unit, the default `127.0.0.1:5900` bind and the Local
Network Access switch. One behaviour changes, in the GNOME backend `wayland-vnc-grd`: a
session now follows a resize of the mirrored monitor instead of freezing on its last
frame.

## Highlights

- **SonarQube Cloud runs beside the pinned linters**, locally and in CI, over one shared
  `sonar-project.properties` so a finding on a laptop is the finding CI reports. The
  quality gate blocks the build. `scripts/run-sonar-scan.sh` feeds it coverage from the
  same pinned pytest run the >=90 % per-file gate reads, so the two cannot disagree.
- **A real bug in the release build.** The AppImage step chose its appimagetool checksum
  from a `case` with no default, so an unexpected architecture reached `sha256sum -c`
  with an empty checksum and the build refused a "tampered" tool it had never heard of.
  Seven other switches gained the default they were missing.
- **Two super-linear regular expressions** in the Android qualification harness now match
  in linear time.
- **Eighteen `pytest.raises` blocks** built their own fixtures inside the block, so a
  failure in the set-up would have read as the refusal under test. Four tests patched
  module globals by hand and left them patched on failure; they use `monkeypatch` now.
- **Eighteen functions split** along seams they already had, including an image-evidence
  band scan that existed twice and the settings-app end-to-end driver's 600-line `main`.
  Its 88 checks and 25 scenario banners are unchanged and it still passes on all seven
  platforms it runs on.
- **Ninety-two composite assertions** split one condition per assert, and sixty shell
  conditionals moved to `[[`.
- **GNOME: a resize no longer freezes the session.** When the mirrored monitor changes
  size, Mutter ends its screen-cast stream without a word on D-Bus. `wayland-vnc-grd`
  now notices the stream's PipeWire node go away, records the monitor again and sends the
  viewer a DesktopSize update (patch 0009, reported upstream).
- **Refreshed** the Ubuntu 26.04 base-image digest pinned by every fixture Dockerfile and
  package smoke. All other pins were already current.

## Install

```sh
sudo add-apt-repository ppa:ventura8/wayland-vnc
sudo apt update && sudo apt install wayland-vnc
sudo apt install wayland-vnc-grd   # GNOME desktops
```

Or from the assets below -- `.deb`, `.rpm`, Arch `.pkg.tar.zst`, AppImage, Flatpak and
Snap, with a `SHA256SUMS` manifest. Verify first:

```bash
sha256sum --ignore-missing -c SHA256SUMS   # checks only the assets you downloaded
sudo apt install ./wayland-vnc_1.0.1_all.deb
```

## Status

**No desktop is release-qualified at this tag.** The gate stays red until all fourteen
target/viewer pairs pass on a trusted runner and their records are published to the
evidence store for the exact tagged commit.

The campaign ran on this branch in KVM guests with the actual RealVNC viewers, desktop
and Android (signature-pinned). Sway, Wayfire, Xfce on labwc and LXQt on labwc passed
every scenario with both. KDE Plasma passed every runnable scenario with the Android
viewer (`portal-revoke` cannot be driven). GNOME passed all but `lock`: GNOME Shell ends
remote sessions while the screen is locked, by design. Hyprland is blocked by an upstream
aquamarine defect on a live switch to 4K. Every fix moved the tree, so all fourteen pairs
must run again on the tagged commit.

A blocked target is not a passed one, and this release claims none of them. See
[docs/releases/v1.0.1.md](https://github.com/ventura8/wayland-vnc/blob/v1.0.1/docs/releases/v1.0.1.md)
for the evidence behind each verdict.
